# UI 规范

> 间距、字号、卡片结构与交互状态的规范。新增页面前先读本页。

## 1. 间距：只允许 10 个值

| 令牌 | 值 | 用在哪 |
|---|---|---|
| `--sp-hair` | 2px | 分隔线、圆点的贴边 |
| （无令牌） | 0 | 显式清零，直接写 0 |
| `--sp-1` | 4px | 图标与文字、徽标内边距 |
| `--sp-2` | 8px | 紧凑控件内部（按钮、chip、输入框） |
| `--stack` | 12px | 卡片内堆叠（`--sp-3` 的别名） |
| `--sp-4` | 16px | 键值对的左右分栏、紧凑卡片组 |
| `--gap-card` | 18px | 卡片之间、区块之间 |
| `--sp-5` | 20px | 通用中间档 |
| `--pad-card` | 24px | 卡片内边距（四边一致） |
| `--sp-7` | 32px | 大块内容之间 |
| `--sp-page` | 40px | 页面左右内边距 |

**不在此表的间距值视为错误**。历史代码出现过
`3 / 5 / 6 / 7 / 9 / 10 / 11 / 13 / 14 / 22 / 30 / 34 / 43 / 67`，
属历次改动累积，不是设计决定；就近归到本表：

| 旧值 | 归到 | 判断依据 |
|---|---|---|
| 3 / 5 | 4 | 微间距 |
| 6 / 7 / 9 / 10 / 11 | 8 或 12 | 控件内部取 8，块之间取 12 |
| 13 / 14 | 12 或 16 | 同上 |
| 20 / 22 | 24 | 卡片类内边距 |
| 30 / 34 | 32 | 大块间距 |
| 43 / 56 / 64 / 67 / 72 / 80 | 40 或 32 | 版面留白 |

固定结构值（不参与归一，直接写定值）：页面左右 40px、卡片内边距 24px、
卡片之间 18px、表格单元格 `7px 24px`、堆叠 12px。

表格左右 24px 与卡片内边距相同，表头文字才能和上方卡片文字同一条竖线（见 §4 墨迹对齐）。

**行高不写死**（28/52 这类）。行高由内容决定，对齐靠栅格结构。

## 1.5 字号：只有三档 + 展示级

正文及以下**只有三个令牌**，不使用裸 px：

| 令牌 | 值 | 用在哪 |
|---|---|---|
| `--text-2xs` | 11.5px | 表格副行（`cell-title__code`）、侧栏组标题、角标 |
| `--text-xs` | 12.5px | 表头、badge、chip、说明文字 |
| `--text-sm` | 13.5px | 正文、表格单元格、按钮、卡片说明 |
| `--text-body` | 14px | 侧栏导航项 |

工具类：`.text-xs` / `.text-sm`。

合并原因：改造前实际在用的是 `10 / 11 / 11.5 / 12 / 12.5 / 13 / 13.5` 七个值，
相邻两档只差 0.5px，属历次改动累积的漂移，不是设计决定。现 12 归到 12.5、
13 归到 13.5，视觉差异不可见，改一处不再牵动全局。

展示级字号（`.page-title` 36px、`.stat__value` 44px、`.detail-stat b` 19px 等）
保留各自的值，以**用得少**维持秩序：一屏只有一个 40px 以上的数字。

## 2. 卡片结构

```
.card
├ .card-head        24px 高：左标题 + 右动作
├ .card-body        margin-top: var(--stack)
│  └ .card-note     说明 / 空态 / 失败，12.5px --fg-3
└

.card--stat         三行 auto + row-gap --stack
├ .stat__label
├ .stat__value      44px / line-height 1 / tabular-nums
└ .stat__delta      12.5px --fg-3
```

规则：

- 卡片内**不嵌套卡片**。状态块（Loading/Empty/Error）放进卡片时传 `bare`。
- 表格放进卡片时不会有额外底色；`thead` 默认透明。
- **表头不吸顶**：`.table-card` 是 `overflow: clip`，不产生纵向滚动容器，`position: sticky` 实际不生效。要吸顶必须先给它 `max-height`，那是另一种交互（表内滚动），不属于默认行为。

## 2.5 全局搜索面板

侧栏第一行是入口，`⌘K` / `Ctrl+K` 在任意页面打开同一个面板。

- 输入 ≥2 字才查，四类并行：影片（`/api/video/search`）、音乐（`/api/music/song/search`）、
  片单（`/api/watch?name=`）、求片（`/api/seek` 的 `video_title`）
- 每组最多 5 条，谁先返回谁先显示；真机上四个接口各 1.2–1.8 秒，等齐再渲染会有空窗
- ↑↓ 选择、Enter 打开、Esc 关闭；每组的「查看全部」跳对应列表页并带上查询词
- 不纳入商品与用户：商品搜索必须带 `seller_id`，用户没有全局搜索接口
- 面板本身不进 URL（瞬时动作）；需要可分享的结果时用「查看全部」跳到列表页

## 3. 危险动作分档

表格里的动作只有两档，不允许再平铺：

- 常规动作：`.btn--quiet` → `--fg-3`，hover `--fg`
- 危险动作：`.btn--danger-text` → 常态同灰，hover `--c-red`
- 一组动作之间 `gap: 12px`（不是 4px）

原因：`.table .btn` 的特异性 (0,2,0) 高于 `.btn--danger` (0,1,0)，因此必须显式写 `.table .btn--danger-text`，否则红色不生效。

## 4. 尾部动作对齐（墨迹，不是盒子）

行内动作与标题**墨迹对齐**，不按盒子对齐；否则按钮自身的 padding 会叠加在卡片 padding 上，右侧比左侧多缩 13px。

| 场景 | 做法 |
|---|---|
| 卡片头部文字动作 | `padding: 0`、无边框底色，20px 高，hover 只变色 |
| 图标按钮（26/28 盒） | `margin-right: -6px`（抵消 `(盒−图标)/2`） |
| 表格最后一列文字按钮 | `padding: 0`，单元格内边距 24px |

核对值：概览签到卡左右各 25px；表格末列文字按钮与表头左边缘同为 1112px。

### 表格对齐：一律左对齐

表头和内容都左对齐，数字列同样。`text-align: right` 不用于任何表格单元格：
一列右对齐、一列左对齐时，视线每跨一列都要重新找起点。

数字列只保留 `font-variant-numeric: tabular-nums`（等宽数字，读数不跳动）。

## 4. 交互状态

- **hover 只改前景颜色**。不铺底色、不位移、不加阴影。
- 加载态只留骨架，不同时显示"正在读取"文案。
- 取不到数据时显示 `—` 或一句说明，不显示成 0。
- 写操作失败必须说清原因（全局 `MutationCache.onError` 已兜底，带状态码）。

## 4.1 请求编排

- **慢接口不阻塞整页**：不同来源的数据拆成独立 query，各自加载、各自渲染。
- 同一屏超过 3 个并行请求时，先区分必需项与可后到项。
- 实测该实例的接口耗时差异极大：`/api/user` 2–5s、`/api/ban/list` 5–11s、`/api/carrot/current` 20s 超时、`/api/user/stats/video/history` 11s 且单次最多 7 天。

## 4.2 布尔参数

后端把查询参数里的布尔值按 **1 / 0** 解析，传 `true/false` 会直接 422。
`client.ts` 的 `buildUrl` 已统一处理：`typeof value === 'boolean'` → `1`/`0`。
新接口直接传布尔，不需要手动 `String(true)`。

## 5. 数字与排版

- 所有数字 `font-variant-numeric: tabular-nums`。
- 统计值 42px、行高 1、单位 17px `--fg-3`。
- 文字重要度阶梯：`--fg` / `--fg-2` / `--fg-3` / `--fg-4`，全部 ≥4.5:1；`--fg-5` 只用于图标与分隔线。
- 中文标题字距 `-0.01em`（`-0.03em` 会使笔画粘连）。

## 6. 动效

| 场景 | 规格 |
|---|---|
| 路由切换 | `page-in` 180ms 淡入 + 滚动复位 |
| 弹窗出现 | `modal-in` 160ms，`translateY(6px)` + 轻微缩放 |
| 进度 | `transform: scaleX()`，不要动 `width` |
| toast | 进入 220ms、出场 180ms（`is-leaving` 标记） |
| 遮罩 | 与面板同时进入，140–160ms 透明度 |

禁止：回弹/弹性曲线、逐行错峰淡入、卡片 hover 位移、数字滚动。全部尊重 `prefers-reduced-motion`。

## 7. 文案

- 动作名即结果名（"发布" → "已发布"）。
- 空态给下一步，不给情绪："还没有片单，建一个把想看的攒起来～"
- 删除需说明后果与可否恢复；**不承诺不存在的功能**（例如写「可从回收处恢复」而回收站没有该入口）。
- 问候类文案按天轮换，避免每天看到同一句。

## 8. 权限与四态

对象级权限来自接口返回，不在前端推断：

| 权限位 | 出处 | 影响的动作 |
|---|---|---|
| `is_can_edit` | 直播源 | 编辑 / 删除源 |
| `is_edit_video` | 片单 | 增删片单内影片 |
| `is_self_upload` | 媒体 / 字幕 | 删除或移动他人内容 |
| `is_can_claim` | 求片 | 认领 |
| `is_can_restore` | 回收站资源 | 恢复 |
| `is_self` | 片单 / 线路 | 编辑与删除 |

规则：**无权限就不给动作，也不给说明**。

可点的才是功能，不可点的不占位置。写「只读」「他人创建」「非维护者」
只是重复「此处无内容」，不产生新信息。

- 混排表格（部分行可操作）：不可操作的行留空
- 整表不可操作：连「操作」这一列一起不渲染

**未验证**：以上四处按字段规范书写；当前只有管理员账号，无非管理员数据可触发
这些分支，需普通用户 token 才能真机确认。

未覆盖：影片详情的资源/字幕行、歌曲详情。
