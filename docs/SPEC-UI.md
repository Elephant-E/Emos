# UI 规范

> 间距、字号、卡片结构与交互状态的规范。新增页面前先读本页。

## 1. 间距：只允许 10 个值

| 令牌 | 值 | 用在哪 |
|---|---|---|
| `--sp-hair` | 2px | 分隔线、圆点的贴边 |
| （无令牌） | 0 | 显式清零，直接写 0 |
| `--sp-1` | 4px | 图标与文字、徽标内边距 |
| `--sp-2` | 8px | 紧凑控件内部（按钮、chip、输入框） |
| `--stack` | 12px | 卡片内堆叠（`--sp-3` 的别名） |
| `--sp-4` | 16px | 键值对的左右分栏、紧凑卡片组 |
| `--gap-card` | 18px | 卡片之间、区块之间 |
| `--sp-5` | 20px | 通用中间档 |
| `--pad-card` | 24px | 卡片内边距（四边一致） |
| `--sp-7` | 32px | 大块内容之间 |
| `--sp-page` | 40px | 页面左右内边距 |

**不在此表的间距值视为错误**。历史代码出现过
`3 / 5 / 6 / 7 / 9 / 10 / 11 / 13 / 14 / 22 / 30 / 34 / 43 / 67`，
属历次改动累积，不是设计决定；就近归到本表：

| 旧值 | 归到 | 判断依据 |
|---|---|---|
| 3 / 5 | 4 | 微间距 |
| 6 / 7 / 9 / 10 / 11 | 8 或 12 | 控件内部取 8，块之间取 12 |
| 13 / 14 | 12 或 16 | 同上 |
| 20 / 22 | 24 | 卡片类内边距 |
| 30 / 34 | 32 | 大块间距 |
| 43 / 56 / 64 / 67 / 72 / 80 | 40 或 32 | 版面留白 |

固定结构值（不参与归一，直接写定值）：页面左右 40px、卡片内边距 24px、
卡片之间 18px、表格单元格 `7px 24px`、堆叠 12px。

表格左右 24px 与卡片内边距相同，表头文字才能和上方卡片文字同一条竖线（见 §4 墨迹对齐）。

**行高不写死**（28/52 这类）。行高由内容决定，对齐靠栅格结构。

## 1.5 字号：只有三档 + 展示级

正文及以下**只有三个令牌**，不使用裸 px：

| 令牌 | 值 | 用在哪 |
|---|---|---|
| `--text-2xs` | 11.5px | 表格副行（`cell-title__code`）、侧栏组标题、角标 |
| `--text-xs` | 12.5px | 表头、badge、chip、说明文字 |
| `--text-sm` | 13.5px | 正文、表格单元格、按钮、卡片说明 |
| `--text-body` | 14px | 侧栏导航项 |

工具类：`.text-xs` / `.text-sm`。

合并原因：改造前实际在用的是 `10 / 11 / 11.5 / 12 / 12.5 / 13 / 13.5` 七个值，
相邻两档只差 0.5px，属历次改动累积的漂移，不是设计决定。现 12 归到 12.5、
13 归到 13.5，视觉差异不可见，改一处不再牵动全局。

展示级字号（`.page-title` 36px、`.stat__value` 44px、`.detail-stat b` 19px 等）
保留各自的值，以**用得少**维持秩序：一屏只有一个 40px 以上的数字。

## 2. 卡片结构

```
.card
├ .card-head        24px 高：左标题 + 右动作
├ .card-body        margin-top: var(--stack)
│  └ .card-note     说明 / 空态 / 失败，12.5px --fg-3
└

.card--stat         三行 auto + row-gap --stack
├ .stat__label
├ .stat__value      44px / line-height 1 / tabular-nums
└ .stat__delta      12.5px --fg-3
```

规则：

- 卡片内**不嵌套卡片**。状态块（Loading/Empty/Error）放进卡片时传 `bare`。
- 表格放进卡片时不会有额外底色；`thead` 默认透明。
- **表头不吸顶**：`.table-card` 是 `overflow: clip`，不产生纵向滚动容器，`position: sticky` 实际不生效。要吸顶必须先给它 `max-height`，那是另一种交互（表内滚动），不属于默认行为。

## 2.5 全局搜索面板

侧栏第一行是入口，`⌘K` / `Ctrl+K` 在任意页面打开同一个面板。

- 输入 ≥2 字才查，四类并行：影片（`/api/video/search`）、音乐（`/api/music/song/search`）、
  片单（`/api/watch?name=`）、求片（`/api/seek` 的 `video_title`）
- 每组最多 5 条，谁先返回谁先显示；真机上四个接口各 1.2–1.8 秒，等齐再渲染会有空窗
- ↑↓ 选择、Enter 打开、Esc 关闭；每组的「查看全部」跳对应列表页并带上查询词
- 不纳入商品与用户：商品搜索必须带 `seller_id`，用户没有全局搜索接口
- 面板本身不进 URL（瞬时动作）；需要可分享的结果时用「查看全部」跳到列表页
- **未输入时显示最近的活动**，不是一句「输入至少 2 个字」：最近看过
  （`/api/video/record/list`）、我上传的（`/api/video/media/listAll?user_id=`）、
  我的片单（`/api/watch?is_self=1`），各取 4 条，同样可用 ↑↓/Enter
- 没有图的行不占图片位（不留空槽）；标题允许与有图的行起点不同

## 2.6 图片位：比例跟着数据走

不要把所有缩略图统一成长方形。实测各类图片的真实尺寸：

| 用在 | 数据字段 | 实测 | 组件用法 |
|---|---|---|---|
| 影片、求片 | `video_image_poster` | 185×278（2:3 竖版） | `<Poster>` 默认，28×42 |
| 片单（列表与详情头） | `image_poster_url` | 600×495 / 1280×720 / 1920×1080（横版） | `shape="wide"`，44×25 / 详情头 128×72 |
| 直播频道 | `image_poster_url` | 频道 logo | `shape="square"`，表格里 28×28 |
| 商品、订单 | `cover_url` | 用户上传方图 | `shape="square"`，表格里 28×28；网格里 1:1 |
| 用户 | `avatar` | 方形头像 | `<UserCell>`，表格里 28×28 圆形 |
| **音乐（歌曲/专辑/歌手）** | `image_poster_url` | **实测全为 null** | 不渲染图片，标题直接起头 |

规则：

- 字段实测恒为 null 的，不要放图片位（首字方块是假图，会让人以为在加载）
- **没有图就不占位**：不画空框、也不留空白列宽（宁可同一列表里两行的标题起点不同，
  也不要一排望不到内容的空槽）
- 缩略图圆角统一 3px（`.poster-img` / `.thumb` / 面板里的 28px 方图共用）：
  在 28px 上给 6px 会圆到像椭圆，看着像头像框而不是缩略图
- 用户不要用海报框去套头像；列表里的用户一律走 `<UserCell>`
- 有图/无图两侧的占位尺寸必须一致，否则数据一加载行高会跳
- **表格里所有缩略图宽度统一 28px**（高度可以按比例不同）：表头的左内边距是按
  「内边距 + 缩略图宽 + 间距」算出来的，宽度一变，表头与标题就对不上。
  横版表格用 `.table--thumb-wide`（44px），内边距跟着变量走，不要写死像素

### 列多的表格用 `.table--dense`

7 列以上（订单、基金订单）改用 `table--fixed table--dense`：

- `table--fixed` 让百分比列宽生效，长文本走省略号，不会把最后一列挤出卡片
- `table--dense` 把左右内边距从 24 收到 12，否则固定布局下徽标（已支付/已发货）
  和时间会各自差几十像素放不下

加列之后一定要重新量：卡片有没有横向溢出、每个单元格 `scrollWidth` 是否大于
`clientWidth`（徽标被切一半是最典型的症状）。

## 2.6.1 图片一律走 `ImagePicker`

所有跟图片有关的输入都只有这一个组件，不要在页面里另拼「上传按钮 + 预览 + 地址框」。

| 场景 | 用法 |
|---|---|
| 单张（商品封面、片单封面、店铺封面、直播频道封面、红包封面） | `<ImagePicker value onChange />` |
| 需要图库 file_id 而不是直链（直播封面） | `onChange(url, fileId)` 的第二个参数 |
| 多张（基金凭证） | `<ImagePickerMulti value={urls} onChange />`，同一个弹窗与 slot 样式 |
| 只展示不给改（官方频道封面） | `<ImagePicker readonly />` |

图库里超过一页（服务端固定 15/页）由组件内部滚动加载，调用方不用关心分页。

## 2.6.2 焦点只有一处定义

焦点样式**只能**来自 `src/styles/base.css` 的那一条 `:focus-visible`
（颜色取 `--focus-ring`）。组件不要再自己写 `:focus` / `:focus-visible`：

- 文本控件在浏览器里永远命中 `:focus-visible`，组件再加一份边框/底色就会叠成双层圈
- 反过来「用 `.input:focus { outline: none }` 把全局那条压掉」更糟：等于给单个组件
  开例外，同一语义出现两套实现，改一处必漏另一处

两个必须一起检查的点：

1. **滚动容器会把焦点环切掉**：环比控件宽 4px，祖先 `overflow` 不是 `visible` 时
   左右（或上下）会被裁。`.card-body` 因此只在含表格时才做横向滚动
2. 环的体积固定（2px 宽 + 2px 偏移），容器在边缘留 ≥4px，否则贴边即被裁

自查：对每个可聚焦元素 `focus()` 后取 `outlineWidth/outlineColor` 是否与全局一致，
再沿祖先找 `overflow !== visible` 的节点，比较环矩形是否越界。

## 2.7 每页条数：只在上游支持的地方给选择器

URL 参数统一叫 `page_size`（历史上部分页面用过 `size`，已合并），取值集合
`PAGE_SIZES = [20, 30, 50, 100]`（`src/lib/search.ts`）。

| 页面 | 上游行为 | 界面 |
|---|---|---|
| 媒体库 / 片单 / 求片 / 音乐 / 订单 / 商城 / 回收站 / 线路 | 认 `page_size` | 给选择器 |
| 资金 · 胡萝卜 | 认 `page_size` | 给选择器 |
| 资金 · 基金订单 | 认，但**上限 30**（>30 直接 422） | 只给 20 / 30 |
| 商城 · 商品表格 | 认，但**上限 100** | 20 / 50 / 100 |
| 片单详情 · 影片列表 | **固定 15** | 不给选择器，按响应 `page_size` 算总页 |
| 直播 · 频道列表 | **固定 15** | 同上 |
| 红包 · 领取记录 | **固定 15** | 同上 |

原则：上游真能改的才给控件，改不了的不要放一个点了没反应的开关。
分页器算总页数一律用**响应里的 `page_size`**，不要用请求参数。

上游固定条数的那几个列表（直播 15、红包领取记录 15、片单里的影片 15）
不隐藏页码区，而是在选择器原来的位置写一行只读的「15 / 页」（`.pager__size`，
`--fg-4` 弱化）—— 让用户知道这是固定的，不是坏了。

## 2.8 图标：墨迹必须居中在 16×16 里

所有图标都画在 `viewBox="0 0 16 16"` 的同一套坐标里，容器用 `align-items: center`。
所以**图标的墨迹中心必须是 (8, 8)** —— 路径画在别的坐标空间（比如 13 单位的画布）
再塞进 16 的 viewBox，会整体偏左上，看起来就是「图标比文字高一截」。

自查方法（浏览器里跑）：

```js
// 对每个 svg：墨迹中心 vs viewBox 中心
const bb = svg.getBBox(), vb = svg.viewBox.baseVal
;[bb.x + bb.width / 2 - vb.width / 2, bb.y + bb.height / 2 - vb.height / 2]
// 两项都应在 ±0.5 单位内
```

- 定向图标（`IconChevron` / `IconLeft` / `IconRight`）墨迹本来就窄，只要求中心对齐
- 墨迹边长建议 9–12 单位；明显小于同组（如只占 8/16）会显得比邻居轻
- 图标+文字的光学间距落在 6–13px（`.btn` 的 gap 是 8，图标自带留白会再加 2 左右）

## 2.9 侧栏不放「假可展开」的箭头

侧栏项只有「跳转」一种行为。曾经给片单与账号加过 `chev` 箭头（暗示有二级菜单），
但点了只是跳页、箭头也不旋转 —— 是纯粹的假承诺，已删除。

要加二级菜单先回答两个问题：

1. 目标页面是不是已经有自己的分段？（片单有「全部 / 我创建的 / 我订阅的」，
   账号有「资料 / 邀请」，侧栏再来一份就是重复入口）
2. 侧栏已经 18 项、900 高下需要滚动，展开后只会更长

两个问题都不利，所以维持「一项一跳转」，不做可展开分组。

## 3. 危险动作分档

表格里的动作只有两档，不允许再平铺：

- 常规动作：`.btn--quiet` → `--fg-3`，hover `--fg`
- 危险动作：`.btn--danger-text` → 常态同灰，hover `--c-red`
- 一组动作之间 `gap: 12px`（不是 4px）

原因：`.table .btn` 的特异性 (0,2,0) 高于 `.btn--danger` (0,1,0)，因此必须显式写 `.table .btn--danger-text`，否则红色不生效。

## 4. 尾部动作对齐（墨迹，不是盒子）

行内动作与标题**墨迹对齐**，不按盒子对齐；否则按钮自身的 padding 会叠加在卡片 padding 上，右侧比左侧多缩 13px。

| 场景 | 做法 |
|---|---|
| 卡片头部文字动作 | `padding: 0`、无边框底色，20px 高，hover 只变色 |
| 图标按钮（26/28 盒） | `margin-right: -6px`（抵消 `(盒−图标)/2`） |
| 表格最后一列文字按钮 | `padding: 0`，单元格内边距 24px |

核对值：概览签到卡左右各 25px；表格末列文字按钮与表头左边缘同为 1112px。

### 表格对齐：一律左对齐

表头和内容都左对齐，数字列同样。`text-align: right` 不用于任何表格单元格：
一列右对齐、一列左对齐时，视线每跨一列都要重新找起点。

数字列只保留 `font-variant-numeric: tabular-nums`（等宽数字，读数不跳动）。

## 4. 交互状态

- **hover 只改前景颜色**。不铺底色、不位移、不加阴影。
- 加载态只留骨架，不同时显示"正在读取"文案。
- 取不到数据时显示 `—` 或一句说明，不显示成 0。
- 写操作失败必须说清原因（全局 `MutationCache.onError` 已兜底，带状态码）。

## 4.1 请求编排

- **慢接口不阻塞整页**：不同来源的数据拆成独立 query，各自加载、各自渲染。
- 同一屏超过 3 个并行请求时，先区分必需项与可后到项。
- 实测该实例的接口耗时差异极大：`/api/user` 2–5s、`/api/ban/list` 5–11s、`/api/carrot/current` 20s 超时、`/api/user/stats/video/history` 11s 且单次最多 7 天。

## 4.2 布尔参数

后端把查询参数里的布尔值按 **1 / 0** 解析，传 `true/false` 会直接 422。
`client.ts` 的 `buildUrl` 已统一处理：`typeof value === 'boolean'` → `1`/`0`。
新接口直接传布尔，不需要手动 `String(true)`。

## 5. 数字与排版

- 所有数字 `font-variant-numeric: tabular-nums`。
- 统计值 42px、行高 1、单位 17px `--fg-3`。
- 文字重要度阶梯：`--fg` / `--fg-2` / `--fg-3` / `--fg-4`，全部 ≥4.5:1；`--fg-5` 只用于图标与分隔线。
- 中文标题字距 `-0.01em`（`-0.03em` 会使笔画粘连）。

## 6. 动效

| 场景 | 规格 |
|---|---|
| 路由切换 | `page-in` 180ms 淡入 + 滚动复位 |
| 弹窗出现 | `modal-in` 160ms，`translateY(6px)` + 轻微缩放 |
| 进度 | `transform: scaleX()`，不要动 `width` |
| toast | 进入 220ms、出场 180ms（`is-leaving` 标记） |
| 遮罩 | 与面板同时进入，140–160ms 透明度 |

禁止：回弹/弹性曲线、逐行错峰淡入、卡片 hover 位移、数字滚动。全部尊重 `prefers-reduced-motion`。

## 7. 文案

- 动作名即结果名（"发布" → "已发布"）。
- 空态给下一步，不给情绪："还没有片单，建一个把想看的攒起来～"
- 删除需说明后果与可否恢复；**不承诺不存在的功能**（例如写「可从回收处恢复」而回收站没有该入口）。
- 问候类文案按天轮换，避免每天看到同一句。

## 8. 权限与四态

对象级权限来自接口返回，不在前端推断：

| 权限位 | 出处 | 影响的动作 |
|---|---|---|
| `is_can_edit` | 直播源 | 编辑 / 删除源 |
| `is_edit_video` | 片单 | 增删片单内影片 |
| `is_self_upload` | 媒体 / 字幕 | 删除或移动他人内容 |
| `is_can_claim` | 求片 | 认领 |
| `is_can_restore` | 回收站资源 | 恢复 |
| `is_self` | 片单 / 线路 | 编辑与删除 |

规则：**无权限就不给动作，也不给说明**。

可点的才是功能，不可点的不占位置。写「只读」「他人创建」「非维护者」
只是重复「此处无内容」，不产生新信息。

- 混排表格（部分行可操作）：不可操作的行留空
- 整表不可操作：连「操作」这一列一起不渲染

**未验证**：以上四处按字段规范书写；当前只有管理员账号，无非管理员数据可触发
这些分支，需普通用户 token 才能真机确认。

未覆盖：影片详情的资源/字幕行、歌曲详情。
