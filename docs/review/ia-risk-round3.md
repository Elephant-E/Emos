# 第三轮 · 聚合与快捷操作的交互代价评估

**性质**：只读评估（未改 `src/`，未启动浏览器）
**基线**：任务给的 `432e039`；审查期间 HEAD 前移到 `f6968fb`（改了概览的胡萝卜 0 值显示与 `aria-busy` 过渡，不影响本文结论，行号按当前工作区）
**范围**：`src/views/*.tsx`、`src/components/*.tsx`、`src/router.tsx`、`src/styles/components.css`（影响布局的规则）
**口径**：慢链路（单请求 2–6 秒、偶发超时）。所有"块/请求/Tab 站点"都是静态可数的；高度是按现有 CSS 预算的**估算值**，附公式，可用浏览器复核。

---

## 0. 先把话说清楚：方向没问题，但"塞卡片"是错的载体

聚合本身是对的——侧栏已经从 12 项涨到 **16 项**（`Sidebar.tsx:27-59`），页面从第二轮 18 个涨到 **20 个**（不含 `/login`）。用户的抱怨"页面太多"是真实的。

但**概览不是靠加卡片来聚合的**。理由是成本结构不对：

| 加一个东西 | 增量成本 |
|---|---|
| 加一个**链接/按钮**（工具条里） | 首屏 +48px、Tab 序 +1、四态 +0、请求 +0 |
| 加一张**卡片**（有独立数据源） | 首屏 +~170px、Tab 序 +1~3、**四态 +3**（加载/空/错）、请求 +1、多一个"部分失败"要表达 |

> 一句话判据：**快捷操作做成链接是"聚合"，做成卡片是"搬家"。**

**先给数字**（推导见 §1.2）：概览现在是 **4 个一级块 / 8–11 张卡 / 10 个请求**。判据是 **块 > 4（即第 5 块）或卡 > 8 就必须分栏；块 ≥ 6 或卡 ≥ 13 就必须分 Tab**。也就是说——**概览已经在"该分栏"的线上，再加 4 张快捷操作卡会直接跨进"该分 Tab"**。

下面按你的四个问题给判据和证据。

## 2. 行内执行 vs 跳转页面

### 2.1 五条判据

一个写操作可以**在概览里直接做完**，需要同时满足：

1. **零输入**：除了点按钮，不需要填任何字段（表单 = 跳页）。
2. **影响半径只到自己**：不改变别人的可见状态（改别人 = 需要上下文 + 二次确认 = 跳页）。
3. **可逆或可重试**：重复点击不叠加副作用（扣钱、不可撤 = 跳页或二次确认）。
4. **结果同屏可验证**：做完能在原地看到变化（余额、槽位数），不需要"去另一页确认"。
5. **频次 ≥ 每天一次**：低频操作不配占首屏（放命令面板）。

> 经验法则：**满足 ≥4 条 → 行内；满足 ≤2 条 → 跳页；3 条 → 抽屉（可取消）。**

### 2.2 白名单（可以行内，附必做条件）

| 操作 | 判据命中 | 行内必须配套 |
|---|---|---|
| **签到**（已行内，`OverviewView.tsx:111-117`） | ①②③④⑤ 全中 | 现在是正确示范：`isPending` + 文案「签到中…」+ 成功后原地刷新余额。**保持** |
| **兑换片单槽位** | ②③(需确认)④⑤ | 必须显示**单价**（"200 胡萝卜 / 个"）+ `confirmDialog` 写明余额变化 + `isPending` + 成功后**原地**改槽位数字。注意：现在这按钮在 `/account` 里（重写为 `mutate` + 确认 + `isPending` 了，`AccountView.tsx:208-227`），**挪到概览就能少一次跳页**，但必须带这 4 件事 |
| **订阅 / 收藏 toggle** | ①②(部分)③④⑤ | 乐观更新 + 失败回滚 + 可撤销。②只轻微违反（会改公开订阅数），可接受 |
| **回收站恢复** | ①②③④(中)⑤ | 已在行内做对（`RecycleView.tsx:32-68`，有 busy + 确认） |
| **撤回认领** | ①②③④⑤ | 已在求片详情 Modal 里（`SeekView.tsx:232-241`，有 `撤回中…`），正确 |

### 2.3 黑名单（必须跳页或在详情页内做，不要在概览直接执行）

| 操作 | 违反的判据 | 为什么 |
|---|---|---|
| **封禁 / 解除封禁** | ②③⑤ | 改别人的可见状态、需要理由、需要"这个用户是谁"的上下文（注册时间/邀请人/是否已有封禁记录）、不可逆。**概览里只允许放"打开用户详情的封禁入口"这一层链接，绝不放执行按钮** |
| **删除类**（影片/资源/订单/商品/片单/线路/频道） | ②③⑤ | 不可逆；且需要看到被删对象（名字/编号/影响范围）才确认得了 |
| **上传** | ①⑤ | 文件选择 + 目标选择 + 长任务进度，概览承载不了 |
| **发起求片** | ①⑤ | 需要标题 + 悬赏胡萝卜；且**/seek 现在根本没有创建入口**（见 2.5） |
| **订单发货** | ②④ | 要看到订单号、买家、金额；发错不可撤 |
| **转赠胡萝卜 / 申请服务商** | ②③ | 钱、不可逆；现在分别在 `/pay`（转赠，`PayView.tsx:155-172`）和 404 空态里的申请按钮，位置正确 |
| **任何批量操作** | ①②④ | 需要多选状态 + 影响面预览 |

### 2.4 灰区：想"行内"但过不了黑名单时的三个替代形态

1. **一步链接 + 落地页锚点**：概览只放 `去封禁` → `/users?user=xxx&focus=ban`，落地后自动聚焦到封禁按钮（`autoFocus` 或 `scrollIntoView`）。成本 1 行，用户少一次找。
2. **抽屉（Sheet）**：复用 `Modal`（已有 focus trap + Esc + 焦点归还，`Modal.tsx:21-61`），只装"确认 + 一句上下文"，不放完整表单。
3. **命令面板**：把低频入口（封禁、提交凭证、查用户）收进 `⌘K`，概览不占任何面积。

### 2.5 现有 4 个快捷入口的"落地体检"（`OverviewView.tsx:342-352`）

| 入口 | 落点 | 问题 |
|---|---|---|
| 上传影片 → `/upload` | ✅ 正确 | — |
| **发起求片 → `/seek`** | ❌ **死路** | `/seek` 是管理员处理求片的列表（详情/认领/催片/撤回），**没有任何"发起/新建"入口**（全文无创建按钮）。点过去找不到"发起"，只能一脸问号回来 |
| **兑换槽位 → `/account`** | 🟡 落点偏差 | 不带 `tab` 参数，默认 `tab=profile`；兑换按钮在能力面板下面（需滚动 ~1.5 屏）。应改为 `/account?tab=profile#slot` 或干脆行内做（见 2.2） |
| 账号设置 → `/account` | ✅ 正确 | — |

> **这 2/4 的错位，正是"聚合"最典型的失败模式：把入口收上来，却把"到达后的第一眼"弄丢了。**若继续往概览加 4 个快捷操作，建议同时加一条验收标准：**每个快捷入口在落地页首屏（不滚动）必须能看到它要触发的那个按钮**。

## 3. 合并页面的可达性风险

### 3.1 `/users` + `/users/$userId` 合并（master-detail）

现状：`/users` 是"输入 ID + 最近封禁 5 条"（`UserSearchView.tsx`，89 行）；`/users/$userId` 是完整详情（`UserDetailView.tsx`，含封禁/解封）。

| 维度 | 现状 | 合并后（若不特意处理） | 需要的补救 |
|---|---|---|---|
| **返回** | 两次历史：列表 → 详情，后退回列表 | 若详情用组件 state：后退**直接离开 `/users`**，搜索框内容也丢 | 详情必须进 URL（`?user=`）；用 `push` 不用 `replace` |
| **深链接** | `/users/eK98L0NEMs` 可分享；**4 处内部入口**指向它（`AccountView.tsx:303`、`:454`、`OrdersView.tsx:104`、`UserSearchView.tsx:74`） | 改成 `?user=` 后旧链接 404（TanStack 会走 notFound） | 保留 `userDetailRoute` 做重定向到 `/users?user=$userId` |
| **键盘路径** | 搜索框回车 → 整页切换，焦点落 body（本来就没做 focus 管理） | 焦点**停在搜索框**，详情出现在下方但读屏无提示（无 `aria-live`、无 `role=region`、无 focus 转移） | 选中后 `focus()` 到详情区标题（`tabIndex={-1}` + `aria-labelledby`），或加 `aria-live` 播报"已加载 xxx" |
| **刷新** | 刷新即回到该用户详情 | 若详情靠 state：刷新后**详情消失**，只剩搜索框，用户以为查不到这个人 | URL 驱动 + `staleTime`（`useUserPayInfo` 已有 5 分钟缓存，`queries.ts:617-630`） |
| **滚动复位** | `AdminLayout.tsx:13-15` 只监听 `pathname`，`key={pathname}` 也只认 pathname | `/users?user=A` → `?user=B`：**pathname 不变 → 不复位滚动、不重挂载**，新结果可能出现在视口之外 | 把 `userId` 也纳入 key：`key={pathname + search.user}`，或选中后 `scrollTo({top:0})` |
| **标题/面包屑** | 两页各自有 PageHeader | 合并后 PageHeader 只有一个，标题要随选中用户变化，否则永远停在"用户/查询" | `title={name ?? '查用户'}`，面包屑第二段跟随选中用户 |
| **空态** | 两页各有空态（"没有封禁中的用户" / "没有服务商权限"） | 新增一个**从未存在**的状态：**"还没选用户"**——首次进入会看到一块空详情区 | 必须补，否则首屏是一块空白卡 |

**结论**：可以做，但要付 4 个新失败模式（后退、深链、刷新、滚动）+ 1 个新状态（未选择）。
**更省的同效果替代**（推荐先试）：**把 `/users` 的输入框搬到 `/users/$userId` 顶部**（或让侧栏搜索框支持"输入 ID 回车 → 用户详情"，`Sidebar.tsx:91-104` 已有回车逻辑，只是写死跳 `/library`）。这样页面数从 2 变 1，但**路由、返回、深链、刷新全部零改动**——因为没有改变"一个 URL 一件事"。

### 3.2 `/pay` + `/fund` 合并

现状：`/pay`（`PayView.tsx`：服务商状态 / 404 引导申请 / 查单 / 转赠，全本地 state）；`/fund`（`FundView.tsx`：订单列表 `?page&size` + 新建订单 Modal + 提交凭证 Modal）。

| 维度 | 风险 |
|---|---|
| **四态冲突（最严重）** | `/pay` 的 404 是**整页级**：`PayView.tsx:45-76` 用 `EmptyBlock` 说明"实例没开通支付"，并把后面所有卡片 `display:none`（:78、:104）。`/fund` 的失败是**列表级**。合并后一个 404 会让用户以为"基金也没了" → 必须改成**分区级状态** |
| **不可逆花钱操作同屏变 3 个** | 申请服务商（扣 5000，不可退，`PayView.tsx:50-70`）+ 转赠（不可撤回，:155-172）+ 新建基金订单。三个都在页面主按钮区，误点半径显著变大 |
| **分页状态归属** | fund 的 `?page&size` 合并后必须加 `&tab=fund`，否则 `/pay?page=2` 语义不明，刷新会落到错的分区 |
| **深链接** | `/fund?page=2` 已有侧栏入口（`Sidebar.tsx:53`）；合并后需重定向，否则书签失效 |
| **键盘** | Tab 序会跨两个业务域（查单 → 转赠 → 订单列表 → 提交凭证），12+ 站点；而 tab 仍是 `role="tab"` **无方向键**（两轮未修）→ 键盘用户切换必须 Tab 到 tab 再 Enter |
| **刷新后表单状态** | 查单结果在 `lookup` 本地 state（`PayView.tsx:23`）；合并后切 Tab 再切回，结果消失（无 URL），用户以为没查到 |

**结论**：并成一条路由**可以做**（`docs/review/ia-round3.md` 建议的 `/fund?tab=merchant|fund|carrot` 资金域就是这种），但上面 5 条风险是硬成本，必须逐条兜住。
替代落法（更省、零退化）：**同一视图、两个路由**——`/pay` 与 `/fund` 渲染同一个外壳，tab 由 `pathname` 决定而不是 state，`/fund` 保留为重定向入口。收益一样是"用户感知页面少一项"，但**深链、返回、刷新、书签全部不用改**。

### 3.3 合并前必须满足的 4 个前提（可当 checklist）

1. **状态全部进 URL**：选中的对象、tab、分页、展开/折叠——每多一个 state，就多一个"刷新会丢"。
2. **旧路由重定向保留**：至少一个 release 周期，`/users/$userId`、`/fund` 都要能落到新位置。
3. **视口内切换要有焦点与播报**：配合 `AdminLayout` 的 `key`，把选中对象纳入 key，并 `focus()` 到新区块标题。
4. **区块级四态**：一个区块失败不能吞掉整页，尤其 404（`/pay` 是现成反例）。

### 3.4 顺带说：这几个"合并"其实已经做对了

`/music`（歌曲/专辑/歌手）、`/account`（资料/邀请/胡萝卜/封禁）、`/whisper`（收/发）、`/shop`（商品/分类/店铺）、`/recycle`（资源/影片）、`/seek`（求片详情用 Modal 而非新页）—— 都是"一个路由多分区"。**这正是应该复制的形态**：分区用 tab，状态进 URL（`?tab=`），详情用 Modal（focus trap 已具备）。

反过来，**最值得"合并"的候选**是 `AccountView` 的「封禁」tab → 整体并入 `/users`（那里已经有"最近封禁"），account 少一个 tab、少一套四态、少一个请求。

### 4.2 聚合一定会让四态变复杂的三类

1. **多数据源页面**（概览、account、pay+fund）：错误态从"页面一种"变成"每块一种"。现状证据：概览 8 个数据源只有 1 个带重试的错误块（另 3 个只有一句文案）；account 有 5 个查询，也只有 `session` 一处 `ErrorBlock`。
2. **master-detail**（/users）：从"两页各一套"变成"一页三套"（未选择 / 详情 / 侧表），并且**新增一个从来没设计过的状态**。
3. **有 404 语义的页面**（/pay）：页级空态会吃掉兄弟区块，必须降级为区块级。

### 4.3 反而变简单的三类

1. **tab 合并**（/music、/shop、/recycle、/whisper）：N 个视图共享 1 套骨架/空/错，成本从 3N 降到 3。
2. **详情用 Modal**（/seek 详情、/fund 凭证、/account 邀请）：0 新增页面、0 新增四态，`Modal` 的 focus trap 已经解决键盘问题。
3. **低频页并入高频页的某个 tab**（account 的封禁 → users）：减少 1 套四态 + 1 个请求。

### 4.4 聚合后的四态预算（可直接贴到 PR 模板）

> **每新增一个"带独立数据源的块" = 3 个状态位 + 1 个失败重试 + 1 个首屏请求 + 1 个 Tab 站点 + 1 个"部分失败"的表达方式。**
> 页面的四态预算 = `数据源数 × 3`。概览现在 **8 个数据源 → 应实现 24 个状态位**；实际只有 1 个满格（session）+ 3 个半格（watching/stats/myWatches 只有文案）≈ 2.5 → **缺口 20 以上**。

也就是说：**想加块，先补状态**。这条比"加不加按钮"更决定用户体感——慢链路下，一块没有错误态的卡，失败时看起来就是"这里本来就没东西"。

### 4.5 本轮顺带确认的两个新问题（影响聚合判断）

- **[P1] `OverviewView` 的待办条会把失败吸收成"没有待办"**：`useTodos`（`queries.ts:203-223`）对三个子请求都 `catch → null`，`todoItems` 用 `(value ?? 0) > 0` 过滤（`OverviewView.tsx:48`）→ 任一接口失败，那一条**整块消失**，用户以为"今天没有待办"。聚合越多，这种"静默降级"越容易被当成正常。
- **[P2] 概览的"我的胡萝卜"在 `carrot` 失败时会走 `session.data.carrot` 兜底**（:131-134），这是对的；但 `stats` 失败只给了一句 `card-note`（:234）没有重试按钮——"失败重试"在概览只有 session 一处。

## 5. 如果一定要聚合：一个成本最低的落法

1. **概览只做"看"**：4 KPI + 2 内容块（继续观看 / 我的近况），把"我的片单"压成一行（`n 个片单 · 查看全部`），给快捷操作腾出首屏。
   （注：`docs/review/ia-round3.md` 主张更强——待办行外再放"能就地执行的工具条"，并把纯导航链接全删。两者不冲突：**它定"放什么"，本文定"每放一个要付多少交互成本、以及放成卡片还是链接"**。）
2. **快捷操作做成顶部 action bar**（方案 B）：3 个高频（上传、求片、兑换）+ 1 个「更多」打开命令面板。
3. **低频入口进 `⌘K` 命令面板**（方案 C）：封禁、查用户、提交凭证、回收站恢复……顺带兑现侧栏那个装饰了两轮的 `⌘K`。
4. **"减少页面数量"用重定向而不是删除路由**：`/pay`↔`/fund` 同一外壳两个入口；`/users` 输入框并入详情页顶部；旧 URL 保留重定向。
5. **每加一个入口，同时加一条验收**：落地页首屏必须能看到目标按钮（这条能立刻抓出 2.5 里"发起求片"那种死路）。

## 附：判定口径

- **块**：一级 `section`（`.cards`）算 1 块；块内每张 `.card` 单独计卡数。
- **请求数**：按 `useQuery` 实际发出的 HTTP 次数统计（`useTodos` 内部并发 3 次，计 3）。
- **四态格**：一个数据源 × {加载, 空, 错}；权限位单独 +1。**"错"格必须"有文案 + 可重试"才算命中**（只有一句 `card-note` 记 0.5 不算满格）。
- **Tab 站点**：`<a>/<button>/<input>` 在正文内、按 DOM 顺序可聚焦的元素数（不含侧栏）。
- **行内可行**：五条判据命中 ≥4；命中 3 条走抽屉；≤2 条必须跳页。
- 高度为 CSS 预算（`--stack:12px`、`.card{padding:24}`、`.cards{gap:18;margin-top:24}`、`.card--stat` 三行 28/42/20），非浏览器实测；如需精确值，按 1.1 的公式在浏览器复核即可。
