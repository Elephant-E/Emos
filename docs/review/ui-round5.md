## 2. 问题清单

### P0（会被看成 bug 或破坏信任）

**P0-1 42px 中文词撑破卡片，被相邻卡片盖掉**
`components.css:1041-1046`（`.card--stat > .stat__value { font-size: 42px; white-space: nowrap }`）
实例：`UserDetailView.tsx:87`「未在封禁记录」、`:115`「由我邀请」；`AccountView` 同款已改 *(已修·工作区)*。
现象（截图）：4 栏卡里第一张显示「未在封禁记」，最后两字被右侧卡片背景盖住 —— 不是省略号，是**硬截断**。
为什么是问题：用户读到的是一个不存在的词；且 6 字状态词和「38,239」用同一档字号，本身就不该。
改法：加一个变体 `.stat__value--word { font-size: 24px; white-space: normal; overflow-wrap: anywhere }`，状态词一律用它；或干脆把状态移出统计位（做成 header 上的 badge）。

**P0-2 回收站工具栏：不存在的工具类导致幽灵文字**
`RecycleView.tsx:104` `<span className="sr-only">搜索</span>`
`components.css` 里只有 `.visually-hidden`，**没有 `.sr-only`** → 这行字真的画出来了（截图：输入框正上方浮着「搜索」，与左侧 select、右侧 tabs 三条基线全不齐）。
为什么是问题：一屏三个控件三种视觉、外加一个来历不明的字，是"没做完"的观感。
改法：`.sr-only` → `.visually-hidden`；同时把 搜索范围 select 与输入框合成一个 `.row-input`（select 宽 96px），tabs 单独放右侧。

**P0-3 H1 把计数吞进标题**
`PageHeader.tsx:23-26`（`hint` 仍是 `<h1>` 内的 `<span>`）
现象（截图）：媒体库「**媒体库 209,486 部**」、直播「直播 77 个频道」、音乐「音乐 572,134 条」、订单「订单 0 单」、资金「资金 0 笔」、片单「片单 8 个」……20 页里 15 页如此。
为什么是问题：① 视觉上标题与计数同一行同一档字号，读成一个长标题，标题失去"我在哪"的锚定作用；② 空数据时出现「订单 0 单」这种自相矛盾的标题；③ 与表脚「共 209,486 条」重复且**量词不同**（部 vs 条）。
改法：`hint` 拆成 `<p class="page-hint">`（13px `--fg-3`，与标题间距 6px）；列表页干脆**删掉页头计数**——表脚已经有了。

## 3. 文案专项（问题 3）

**删过头的 3 处**（都是"下一步"被删掉）：
1. `OrdersView.tsx:72` 空态只有「没有符合条件的订单」——筛选中无结果时没有出口（对比媒体库有「清空筛选」）。
2. `SeekView.tsx:82` 空态只有「这个状态下没有求片」。
3. `UploadView` 队列为空时，页面上只剩「把视频拖到这里」一行 —— 首次使用的人不知道**入库前要先关联影片**（原来那句解释被删了）。建议保留一行 `card-note`：「选中的文件会先识别片名，识别不到会让你手动选」。

**仍是废话的 2 处**：
1. `UserSearchView` 第二句「服务商权限下的余额、观影、注册时间需要额外授权。」—— 用户还没查任何人，先读一段权限免责声明；且它与页面上方的同类说明重复。删。
2. `UploadView` dropzone 副行「支持多选 · 8 MB 分片 · 单文件上限取决于存储」—— 「8 MB 分片」是内部协议细节，对上传者无意义。改「支持多选，大文件会自动分片」。

**保留得对的 5 处**（请勿再删）：
1. `UserDetailView` H1 下「当前账号没有服务商权限，看不到余额、观影权限与注册时间。申请成为服务商后可看全。」—— 解释了整屏的「—」。
2. `LiveView`「你只能编辑自己创建的直播源，别人的源仅可查看。」—— 解释了操作列的「—」。
3. `LinesView`「显示「—」的线路由其他人创建，只能查看。」
4. `RecycleView`「显示「—」的资源是他人上传的，只能查看，不能由你恢复。」
5. `PayView` 转赠卡「单次 2 – 6000 个，转出后不可撤回。」

**空态文案一致性**：`RecycleView`/`LibraryView`/`FundView(基金)` 有 hint；`OrdersView`/`SeekView` 没有；`WhisperView` 有。→ 建议 SPEC §7 补一条：「列表页空态必须包含 ① 现状一句 ② 下一步一句 ③ 可选一个动作」。

## 5. 四态一致性（问题 5）

| 状态 | 现有形态 | 不一致处 |
|---|---|---|
| 加载 | ① `LoadingBlock`（页级表格骨架，8 行）② 卡内 `<div className="skeleton" style={{height:96}}>`（概览/上传）③ 纯文字「读取中…」（`UserSearchView`、`UserDetailView:166`、`OverviewView` 签到卡 small） | **三套**。SPEC §4 要求"加载态只留骨架，不同时显示文案"→ ③ 违规 |
| 空 | `EmptyBlock`（图标 + 标题 + 可选 hint/action） | 组件统一 ✓；但 hint/action 有无不一（§3），且页头还写着「0 条」 |
| 错 | `ErrorBlock`（红图标 + 标题 + 一句人话 + 重试） | 组件统一 ✓；回收站的"错态与空态互斥"已修 ✓；但 `UserDetailView:73` 出错时下面 4 张卡仍渲染成「—」 |
| 权限不足 | 一行 13px 说明（4 处落点不同） | 见 P1-5 |
