# 概览「快捷操作」的反馈设计

范围：只谈概览页（`src/views/OverviewView.tsx`，358 行）新增动作的反馈，不做全站动效审查。
依据：`docs/SPEC-UI.md` §6 现状 + 代码实读，未启动浏览器；引用的行号可直接核对。
前提：`--ease` / `--t-fast` 140ms / `--t-enter` 160ms / `--t-base` 220ms，禁用回弹。

## 0. 先定一条边界：搬动作 ≠ 搬页面

现在的概览有 4 个 `<section>`、最多 11 个可见块：待办 0–3 张 + 四张统计卡 + 继续观看 + 我的近况 + 我的片单 + 快捷入口（待办通常 1–3 张，实战里 9–11 个块）。
把独立页面的动作搬进来是对的（少一次跳转、少一次背路径），但**前提是不新增区块**。

> **规则：概览的块数到此为止。新动作只能挂在已有卡片上——`.card-head` 的尾部动作位，或行内。**

否则"减少独立页面"会变成"再造一个后台首页"，而首页每多一个区块，后面每条动效规则都要多付一次预算。

## 一、先修三处会直接破坏反馈的地方

这三处不修，下面所有设计都落不了地。

### 1.1 `.btn[aria-busy]` 没有过渡也没有延迟

`components.css:980`：

```css
.btn[aria-busy='true'] { opacity: 0.6; }
```

问题：`.btn` 的基础 transition（`:222-223`）只有 background / border-color / color，**不含 opacity**。所以 busy 态是硬切；而且没有延迟，接口 200ms 内返回时按钮会 0.6→1 闪一下。

这条直接影响本轮的 T+0–300ms 窗口：那个窗口要做的事就是"稳稳地告诉手指点到了"，闪一下等于没说。

### 1.2 胡萝卜为 0 时显示 `—`

`OverviewView.tsx:131-133`：

```tsx
{carrot.data?.carrot ?? session.data?.carrot ?? null ? formatThousand(...) : '—'}
```

运算符优先级让它等价于 `(值) ? 数字 : '—'`，而 `0` 是 falsy——实测（node 复核）：`carrot = 0` 输出 `—`。

后果正好撞在「兑换槽位」上：兑换要扣胡萝卜，余额扣到 0 是常见结局，卡片却显示"没数据"。**反馈必须反映真实状态，否则再好的动效都是在解释一个错误。**

### 1.3 三个卡片的骨架高度与终态不一致

`继续观看` 的骨架写死 `height: 96`（`:179`），数据到位后 3 行列表约 132px；`我的近况` 骨架 40+12，终态是 60px 图表 + 说明；`我的片单` 骨架 72，终态 3 行约 108px。

首屏落位时整页会跳 1–3 次，且这三次跳**不是用户造成的**。这比"缺少淡入"更破坏观感——也直接决定了下面 §4 的预算结论（概览禁止 content-in）。

## 二、三类动作的反馈方案

### 2.1 行内执行类（签到、兑换槽位）

#### 三个时间窗回答三个不同问题

不要用一个 spinner 包办全程。用户在这三个窗口里问的是不同的东西：

| 窗口 | 用户在问 | 允许出现 | 明确禁止 |
|---|---|---|---|
| **0–300ms** | 我点到了吗 | `:active` 按下态（已有）；按钮文案同帧切换；`aria-busy` 0.6（140ms 过渡） | 任何入场动画（位移/缩放/骨架） |
| **300ms–1s** | 还在动吗 | 什么都不新增，按钮保持 busy | 第二个 spinner、进度条、再来一条 toast |
| **1–3s** | 是不是卡住了 | 一行静态灰字「网络有点慢，仍在处理…」（1s 后出现，无动画） | 无限旋转的 spinner |
| **>3s** | 我能不能走开 | 同上；允许切页（写操作在后台继续） | **自动重试** |

三个理由值得单独说：

- **0–300ms 不加入场动画**：这一步可能 80ms 就结束，一个 160ms 的入场会被截断成"抖了一下"。这正是把 `--t-enter` 花在错误位置。
- **1s 后才出提示**：这台实例确实有慢接口（`ban/list` 5–11s、`user` 2–5s），但签到通常 <1s；提前出提示等于把快路径也变成"卡"。
- **>3s 不自动重试**：签到与兑换都是**写操作且不幂等**。自动重试一个可能已经成功的写请求，等于重复签到 / 重复扣胡萝卜。

#### 签到：逐帧剧本

现状只有 toast（`:52-60`），触发点是卡片（`:107-126`）。

| 时刻 | 发生什么 | 时长/缓动 |
|---|---|---|
| 点击 | 按钮 立即签到 → 签到中…；`aria-busy` 生效 | 文案同帧；opacity 140ms（延迟 120ms） |
| 成功 | ① 按钮 → 今天已签（disabled，`--fg` → `--fg-5`）② 主数值 `—` → 连续天数 ③ 说明行 → `今天 +N 胡萝卜` ④ toast | ① 140ms 颜色；②③ 直接替换 |
| 失败 | 按钮恢复可点；错误 toast 带原因（全局 `MutationCache.onError` 已兜底） | 0ms |

**关键：② 不要做数字滚动。** 从 `—` 变成 `3` 本身就是全屏最显眼的变化，再滚一遍只会延迟可读性（SPEC 已禁，这里补上具体场景）。

**签到不做乐观更新。** 判定标准：结果里含服务端分配的量（`+N`、`continuous_days`）、不可撤销、失败回滚会刺眼——三条都占。乐观 UI 适合"收藏/点赞"这类可逆、幂等、本地能算准的动作，签到一条不沾。

#### 兑换槽位：同族，但三处不同

现状在 `AccountView.tsx:207-225`：confirm 弹窗 → mutate → toast。搬到概览后的建议：

1. **确认方式改成行内二次确认，不用全屏弹窗。** 为一次"+1 槽位"遮住 11 个区块、迁移焦点、再按 Esc 返回，代价与收益不成比例。做法：第一次点击后按钮原地变「确认兑换 · 扣 N」，颜色转 `--c-yellow`（纯颜色，140ms），2.5s 内再点执行，超时文字自动恢复。
2. **数值变化需要一次提示。** 槽位是 `3 → 4` 的单字符变化，用户点完再看卡片很可能看不出动过。给主数值一次 220ms 的颜色脉冲（`is-bumped`，见 §3.4）。这是本轮唯一建议新增的"一次性"动效——因为它对应的是一个**幅度极小但重要**的状态变化。
3. **必须同时更新胡萝卜卡**：`exchangeSlot` 已 invalidate `['session']` 与 `['carrot']`（`queries.ts:398-410`），两处会一起刷新；但先修 §1.2，否则余额归零时卡片显示 `—`。

#### 「签到只有 toast，够不够」

**不够。但缺的不是动效，是就地状态。**

三条理由：

1. **视线距离**：触发点在左上第 3 段，toast 在右下角。页面上有 11 个块，为读一条 2.6 秒的消息把视线从左上拉到右下，代价远大于任何 160ms 动画。
2. **时长错配**：签到是"今天不会再做一次"的动作，它的结果（连续天数、今天 +N）应当留在页面上；toast 2.6s 后会消失，飘走的是唯一一次解释。
3. **语义错配**：toast 报的是**事件**（发生了什么），卡片显示的是**状态**（现在是什么）。签到同时产生两者，只报事件不更新状态，用户下次扫到这张卡时无法把"3 天连续"和"我刚才点的那下"联系起来。

**toast 不要删。** 它是跨屏兜底：用户在别的页面触发、或操作太慢已经滚走时，只有 toast 还在。两者不是二选一，是"就地"与"记账"的分工。

### 2.2 行内表单类（快速封禁、快速改备注）

#### 决策轴：目标是否已知

| 条件 | 形态 |
|---|---|
| 目标**未定**（入口是个计数/入口卡） | **跳页**。没有对象的表单不是表单，是猜谜 |
| 目标已定 + 单字段 + 可逆 | **内联展开** |
| 目标已定 + 多字段 或 不可逆 | **弹层**（`modal-in` 160ms 已有） |

#### 快速封禁 → 跳页

概览里唯一与"封禁"相关的入口是待办卡「封禁中用户 N 人」（`:47`），它只有计数，**没有对象**。封禁还需要理由字段和二次确认，且不可撤销。

所以：**概览不做封禁，保留跳 `/account?tab=ban`。** 

什么情况下可以改判：入口变成"带行的卡片"（例如卡片里直接列出 2–3 个封禁中的用户），此时行内「解封」是成立的——解封可逆、不要理由、一句话确认即可；行内「封禁」仍不成立（要理由、要对象、不可逆）。

这条不对称是这个设计的重点：**同一个人，解封可以在行内点，封禁不行。**

#### 快速改备注 → 内联展开（但有前提）

前提先讲清楚：**概览目前没有任何带备注字段的行。**「我的片单」和「继续观看」是行列表，但它们的对象没有备注字段；备注的接口是 `inviteApi.remark`（用户备注）和 `shopApi.remarkOrder`（订单备注），对应的行都不在概览上。

所以落地顺序是：先把「待发货订单」从计数卡改成 2–3 行的列表卡 → 行尾出现「备注」→ 点开是内联编辑。**不要为了放这个动作，先造一个列表。**

一旦有行，形态选内联而不是弹层：

- 弹层要为 1 个输入框遮住整屏，还要处理焦点、Esc、点外关闭——成本远大于"顺手记一笔"的收益；
- 跳页会丢掉概览上下文，而备注恰恰是"看到什么想起什么"的顺手动作。

#### 160ms 预算里的进入与退出

| 形态 | 进入 | 退出 | 占用预算 |
|---|---|---|---|
| 弹层 | overlay + panel 同时进入，共用 `--t-enter` 160ms（已落地） | **0ms 瞬时关闭**（已有规则） | 1 个 A 级 |
| 内联编辑 | 位置不动，静态文本被 input 替换，只做 `opacity` 140ms | 保存：140ms 淡回；**取消：0ms** | 1 个 B 级 |
| 跳页 | `page-in` 160ms（已有） | — | 1 个 A 级 |

内联编辑的三条硬约束：

1. **不许动画高度/宽度**——布局属性，会带着相邻行一起跳；概览 11 个块，一次跳版整页都在动。
2. **行高必须预先留好**：input 高度 ≤ 现有行高。现有卡片行（`.row`）是固定行高结构，做成"文本→input"的同位替换，行高不变。
3. **取消不播动画**：取消意味着"什么都没发生"，回退给一个淡出反而像"确实变了"。

#### 一次只能开一个编辑态

第二个行内输入框打开时，第一个先静默关闭（不播动画）。理由：两个未保存的输入框在 11 个区块的页面里，用户无法判断哪个会被提交、提交给谁。

### 2.3 批量 / 危险动作（删除、恢复）

**结论：一条都不放。概览不做删除，也不做恢复。**

四条理由：

1. **概览没有列表上下文。** 批量依赖"表头全选 + 行勾选 + 已选计数"三件套，概览一个表格都没有。硬做就是往卡片里塞复选框——等于把卡片当列表用，和"状态块不是容器"是同一类错误的镜像。
2. **概览省不掉任何一步。** 删除必须展示对象名、影响范围、能否恢复，这些在确认框里；确认框本身就是一个全屏层。也就是说"在概览删"和"在列表删"最终打开的是同一个 dialog，概览只多了"我刚才在哪一页"的困惑。
3. **正确形态是撤销，不是确认。** 批量删除应该配 undo（toast 上带按钮），而当前 toast 只活 2.6s、没有动作位。在没有 undo 的前提下把批量删除搬到首屏＝提高误删率。
4. **恢复是回收站的语义。** 概览最多放一个「回收站 N 条」的**跳页链接卡**，不放恢复按钮。

**允许进入概览的最重动作边界：可逆 + 单对象 + 有就地状态回显。** 签到、兑换槽位、备注、收藏符合；删除、恢复、批量、封禁不符合。

## 三、CSS 草案（对应上面三类动作）

落点：① 改 `components.css` 现有 `.btn` 与 `[aria-busy]`；②–⑤ 追加到 `components.css` 末尾。不新增令牌，不新增第四个缓动。

### 3.1 修好按钮的进行中态（§1.1）

```css
/* 1) 把 opacity 加进 .btn 的基础过渡，busy 结束时才不会硬切 */
.btn {
  transition: background var(--t-fast) var(--ease),
    border-color var(--t-fast) var(--ease),
    color var(--t-fast) var(--ease),
    opacity var(--t-fast) var(--ease);
}

/* 2) 替换原来的单行规则。延迟 120ms：接口 200ms 内返回时根本不显示，避免闪。
      必须写在 .btn:disabled 之后（同权重，靠源码顺序决胜）。 */
.btn[aria-busy='true'] {
  opacity: 0.6;
  pointer-events: none;
  transition: opacity var(--t-fast) var(--ease) 120ms;
}
```

> 恢复时走基础规则（0 延迟），所以"变暗慢半拍、变亮立即"，正好符合点击的心理节奏。

### 3.2 1 秒后才出现的等待提示（§2.1）

```css
/* 元素只在 pending 时渲染；延迟由 CSS 给，JS 不用 setTimeout。
   降级模式下 animation-duration 被压到 0.001ms，但 delay 不受影响，
   仍是 1s 后出现，行为一致。 */
.qa-hint {
  margin: var(--stack) 0 0;
  font-size: 12.5px;
  color: var(--fg-4);
  opacity: 0;
  animation: qa-hint-reveal 1ms linear 1s forwards;
}

@keyframes qa-hint-reveal {
  to { opacity: 1; }
}
```

### 3.3 行内编辑态（§2.2）

```css
/* 同位替换：静态文本换成 input，行高不变，只做透明度。
   不要给这里加 height / transform / grid-template-rows。 */
.inline-edit {
  animation: page-in var(--t-fast) var(--ease);
}

/* 行内输入框必须矮于行高，否则会撑开行、带动相邻行 */
.inline-edit .input {
  height: 24px;
  min-width: 0;
  width: 100%;
  font-size: 13px;
}
```

### 3.4 兑换的二次确认与数值脉冲（§2.1）

```css
/* 二次确认：只改颜色，140ms 由 .btn 的基础过渡提供，不需要额外规则 */
.btn--confirm { color: var(--c-yellow); }
.btn--confirm:hover { color: var(--c-yellow); }

/* 数值的一次性脉冲：仅用于"幅度极小"的变化（如槽位 3 → 4）。
   签到那种 `—` → 数字 的变化不要用。 */
.stat__value.is-bumped {

}

@keyframes stat-bump {
  0%, 100% { color: var(--fg); }
  30%      { color: var(--c-yellow); }
}
```

```css
/* 让落位只跳一次、幅度最小。具体数值以真机量一次为准，
   这里按当前 DOM 行高估算：3 行列表 / 图表 + 说明 / 3 行片单。 */
.card-body--watch { min-height: 132px; }
```

## 四、动效预算

### 4.1 两个数字

> **同屏同时运行的动画 ≤ 2 个；其中「注意力级」≤ 1 个。**

分级定义：

| 级别 | 包含 | 上限 |
|---|---|---|
| **A 注意力级** | 位移、缩放、新图层出现（`page-in` / `overlay-in` / `modal-in` / `menu-in`） | 同屏 ≤ 1 |
| **B 环境级** | 颜色、局部透明度、`progress` 的 `scaleX` | ≤ 2，且不得与 A 级处在同一张卡 / 同一行 |

补充一条互斥规则：**A 级播放的那 160ms 是静默窗口**——这期间不启动任何新动画，需要的话排队到结束后。

### 4.2 为什么是 2

- **1 个不够**：用户动作天然会产生一对——按钮变色（B）+ toast 入场（B）。这是合理的一对，卡到 1 个会逼死设计。
- **3 个就是"整页在动"**：11 个块的密度下，三处同时变化意味着任意相邻两卡都可能有动静。此时人会停止执行、开始扫描"哪里变了"——后台页面最贵的就是这种被打断的注意力税。
- **大脑能并行检测变化，但只能串行判断主次**。两个名额正好对应"我点的东西"和"系统的回执"；第三个名额没有对应的语义角色，只会制造竞争。

### 4.3 概览专属豁免：不做 content-in

第二轮给列表页设计的"加载→内容淡入"**不适用于概览**。

原因具体：概览有 5 个互相独立的 query（session / carrot / watch / stats / todo），它们不同时返回。如果每个骨架块落地都播一次 160ms 淡入，首屏会在 1–3 秒内连续淡入 5 次——而这 5 次**没有一次是用户造成的**，直接违反"动效只回答用户造成的变化"。

配套：先修 §1.3 的骨架高度，让落位只跳一次、且幅度最小。**先让页面不跳，再谈要不要淡。**

### 4.4 概览的预算分配表

| 时刻 | A 级 | B 级 | 合计 | 说明 |
|---|---|---|---|---|
| 首次进入 | `page-in` ×1 | 0 | 1 | 5 个 query 落位不播动画（§4.3） |
| 点击签到 | 0 | 按钮 opacity ×1 | 1 | 主数值、说明行直接替换，不参与计数 |
| 签到成功（约 +300ms） | 0 | 按钮颜色 ×1 + toast 入场 ×1 | **2** | 用满上限；这是唯一允许的两处同帧 |
| 兑换二次确认 | 0 | 按钮转黄 ×1 | 1 | 文字同时换，不额外播动画 |
| 兑换成功 | 0 | 数值脉冲 ×1 + toast 入场 ×1 | **2** | 用满上限 |
| 打开弹层 | `overlay`+`panel` 算 1 | 0 | 1 | 弹层期间不叠加其他动画 |
| 行内改备注 | 0 | `opacity` 140ms ×1 | 1 | 无 A |

## 五、明确不该做的清单

1. **数字滚动**（连续天数、胡萝卜）。SPEC 已禁；这里补具体理由：签到后数值从 `—` 变数字本身就是最大变化，滚动 400ms 只是延迟可读。
2. **卡片 hover 位移 / 缩放 / 阴影**。概览是 11 块网格，鼠标扫过时整屏会持续微抖；且违反"hover 只改颜色"。
3. **签到成功的彩带 / 粒子 / 光环脉冲**。一天触发一次，代码量与回归风险却要背 8 小时。
4. **数值变化后的持续高亮**。超过 300ms 的高亮会被读成"这块被选中了"，而不是"这里刚变"；一次性脉冲上限 220ms，不叠加。
5. **骨架 shimmer 提速，或骨架→内容交叉淡入**。见 §4.3：这是把非用户触发的动画变多，不是变少。
6. **行内编辑的高度 / 宽度展开动画**。布局属性；会让相邻行跟着跳。
7. **批量选择的复选框入场动画**。批量本身不进概览（§2.3），没有承载它的地方。
8. **toast 加「撤销」按钮 + 倒计时进度条**。方向是对的（比确认更好），但当前 toast 无动作位、活 2.6s、最多 5 条，做半套会比不做更糟。等 toast 支持动作位再谈。
