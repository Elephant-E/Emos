### 配置 / 构建（这类问题不会报错，但会悄悄失效）

- `vite.config.ts` 改用 `loadEnv` 读 `VITE_API_ORIGIN`：原来直接读 `process.env`，
  而 Vite 是在解析完配置**之后**才加载 `.env*`，所以按文档改 `.env.development` **根本不生效**
- 生产构建不再产出 sourcemap（`dist` 整目录上传到 Assets，`.map` 会连源码一起公开）
- `tsconfig.include` 补 `worker`：后端代码此前完全不在类型检查范围内
- worker 去掉无效的 `headers.set('Host', …)`（Workers 忽略该头）；上游不可达统一 504；
  非 JSON 响应保留上游状态码（原来一律改写成 502）
- 生成脚本加 npm 入口 `npm run docs:api`，并加 `.github/workflows/docs-check.yml`：
  重跑后 `docs/` 有差异就红，同时跑 `typecheck`

## 三、后续可选（都不阻塞当前使用）

1. **维护模式检查**：旧项目启动即判 `isMaintenance`，当前没有。
2. **CI 加一条 e2e 冒烟**：现在 CI 只做类型 + 文档漂移，页面级回归仍靠手动。
3. **`docs/api-reference.md` 的标题层级**：分组深度不同会让 `###` / `####` 混用
   （`grep -c '^#### '` = 109，接口 190 个）。
4. **`SpotifyArtists` 那类裸 `fetch`**：已经没有了（随按名字搜索一起删除）；
   若将来再接自定义端点，走 `api/client.ts` 的 `request()`。
5. **上传页识别**：`parse-torrent-title` 在「第 10 集」这类中文集数标记上无效，
   区间集（`S01E01-E30`）只取首个。若以后要更准，需要新的解析源。

