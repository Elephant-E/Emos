3. **一次一处、编译一次、点开一次**：整文件跑正则的代价是「确认键点了没反应」这类
   类型检查抓不到的 bug（这轮共修掉 8 处）。
4. **纯计算进 `lib/`**：`invite-tree`、`upload-resolve`、`concurrency`、`clipboard`。

# 页面标题与内容的间距（2026-11-15）

现象：音乐停用页的标题与下方说明贴在一起（0px）。

根因不是那个页面写错，而是整站的间距一直是靠 `.toolbar` 的 `margin-top` 撑开的：
没有工具栏的页面（整页只有一句说明、或只有一张卡）就完全没有间距。

改法：把这段间距收到 `.page__head` 上（`margin: 0 auto var(--gap-card)`）。
它与下一个元素的 `margin-top` 相邻折叠，所以原本有工具栏的页面数值不变（仍是 18px），
缺工具栏的页面自动补上 18px。

实测 9 个页面（音乐、歌曲详情、媒体库、抽奖、账号、上传、商城、用户、回收站）：标题到内容一律 18px。

# 登录后弹回登录页（2026-11-15，已修）

现象：令牌校验通过、也没有报错，但一直停在登录页，进不去后台。

原因：`LoginView` 里的 `setToken` 是组件内的 `useState` setter，把 `api/client` 的
`setToken` 遮住了。校验成功后只更新了输入框的值，**没有写进 localStorage**；
而路由守卫读的是 `getToken()`，于是判定「未登录」，`beforeLoad` 立刻 redirect 回 `/login`。

为什么之前测试没发现：守卫的条件是 `!getToken() && !USE_MOCK`，
mock 模式下整段被跳过，所以本地一直"看起来能登录"。这类「只在真后端才出现」的分支，
以后要在 `npx vite`（真后端）上验，而不是 mock。

修法：`import { setToken as persistToken } from '@/api/client'`，校验通过后 `persistToken(trimmed)` 再 `onDone()`。
输入框仍用组件内 state，两者职责分开：一个是"正在输入的字符串"，一个是"已生效的凭证"。

真后端实测（`vite --port 5291`）：

- 令牌登录 → 落到 `/`，侧栏渲染，`localStorage.emos_admin_token` 有值
- 回跳形式 `/login?token=…` → 自动校验并落到 `/`，同样写入本地
- 清空本地后直接访问 `/library` → 被弹回 `/login`（守卫仍生效）

# em / rem 间距排查（2026-11-15）

起因：间距巡检里除了 4/8/12/16/18/20/24 这些 token 值，还冒出 `6.25px`、`6.75px`、`3px`。

## 结论：不是我们的样式，也不是 em 写的间距

1. **布局间距里没有任何 em/rem**：`margin*` / `padding*` / `gap` 三个属性在
   `base.css` / `components.css` / `tokens.css` 里命中 em 的数量为 **0**；全站也没用过 `rem`。
2. em 只出现在两处，都是随字号缩放才正确的地方：
   - 19 处 `letter-spacing`（字距）
   - `.page-title__hint` 的 `font-size: 0.62em` + `vertical-align: 0.28em`（标题旁说明，跟着标题字号缩放）
3. 巡检里的"异常值"来自**浏览器默认样式**：
   - `<option>` 的 `gap` = 0.5em → 12.5px 字号下是 6.25px、13.5px 下是 6.75px
   - `<input type="checkbox">` 的 UA `margin` = 3px
   这两类元素不在我们的 CSS 里，改不到也不该改。

## 以后巡检怎么避免误报

扫描计算样式时排除 UA 自带样式的元素（`option`、`input`、`button`、`select`、`textarea`），
否则每次都会把这几个值当成"跑出刻度"。

# 两处「看起来像补丁、决定保留」的地方（2026-11-15）

补丁清理做到第三批后停手。下面两处是刻意保留的，理由记在这里，避免以后反复讨论。

## 1. `LoginView` 的 `eslint-disable-next-line react-hooks/exhaustive-deps`

自动提交只在**挂载时**跑一次（从 URL 里取回跳令牌）。要消掉这行 disable，得把
`submit` 包成 `useCallback`，而它依赖 `onDone`——那是 `router.tsx` 里现写的箭头函数，
每次渲染都是新引用，dependency 仍不稳定；要么给 router 传稳定回调，要么加 `useRef` 守卫，
两种都是为一个"只跑一次"的副作用引入额外间接层。

判断：保留一行带注释的 disable，比加一层绕路更诚实。

## 2. 11 处 `as unknown as`

全在 API 边界（`queries.ts` 的适配层、`use-upload-queue` 的上游 recognize 返回）。
上游这些接口返回的是宽松 JSON，没有可依赖的 schema。要彻底去掉，得为每个响应写运行时
类型守卫；而后台管理端对这些字段只做展示，收益低于维护成本。

判断：保留，但要求「每个 cast 旁边必须有注释说明为什么」。当前 11 处都满足。
